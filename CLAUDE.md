# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Обзор

Веб-версия игры «Шпион» на русском языке. Один Go-бинарник отдаёт статический фронтенд (`static/index.html`) и WebSocket-эндпоинт `/ws`, через который проходит вся игровая логика, — всё состояние держится в памяти. Ни базы, ни внешних сервисов.

## Команды

```bash
go run .                      # Локальный запуск на :8080
go build -o spy .             # Сборка бинарника
docker compose up --build     # Сборка и запуск в контейнере (порт 8080)
```

Проверки: `go test ./...`, `go vet ./...`, `node --test frontend.test.cjs`. Отдельной сборки фронтенда нет — `static/index.html` это один самодостаточный файл (HTML + CSS + JS), который отдаётся напрямую через `http.FileServer`.

## Архитектура

Сервер и обработчик WebSocket находятся в `main.go`; круги вопросов, подтверждения и общее голосование — в `turns.go`. Всё состояние хранится в двух in-memory мапах под мьютексами; при рестарте теряется.

- **Глобальная `rooms`** (`map[string]*Room`, под `roomsMu`) — ключ это 4-символьный код комнаты.
- **`Room`** владеет своим `sync.Mutex`, который защищает `Players`, `State`, `Accuse` и флаги `Alive`/`IsSpy`/`Connected` у игроков. Все хендлеры следуют одному паттерну: взять лок, сделать снапшот нужного (часто копия `Players` в локальный слайс), отпустить лок, и только потом делать I/O (`send`/`broadcast`) по снапшоту. **Нельзя** держать `r.mu` во время `Conn.WriteJSON` — у `Player.send` свой мьютекс на соединение, и broadcast под локом комнаты даёт дедлок.
- **`Player.send`** сериализует записи в одно соединение. Всегда пиши через него, а не напрямую в `Conn.WriteJSON`. Для оторванного соединения `Conn == nil` — `send` тихо возвращается.
- **Жизненный цикл комнаты**: `lobby` → `playing` → (`voting` ↔ `playing`)* → `over`. Переходы происходят в `startGame`, `startAccuse`, `submitAccuseVote`, `handleSpyGuess` и `endGame`. `endGame` идемпотентен (проверяет `State == "over"`) и сохраняет payload в `LastGameOver`, чтобы реконнект мог его переиграть.
- **Жизненный цикл соединения с grace period**: `handleWS` создаёт один `Player` на сокет и крутит цикл `ReadJSON`. При обрыве `defer` **не удаляет** игрока — он помечает `Connected = false`, зануляет `p.Conn` и запускает `time.AfterFunc` на `graceLobby` (60с) или `graceGame` (5м) в зависимости от `State`. Таймер зовёт `Room.removeDisconnected`, который уже по-настоящему удаляет игрока, переназначает хоста (предпочитая `Connected` игроков) и удаляет пустую комнату. Если удалённый игрок был последним живым шпионом/мирным в активной игре — здесь же вызывается `endGame`. Реконнект отменяет таймер и переиспользует тот же `Player`. Чтобы старый defer не затёр новый `Conn` после swap, он сравнивает `p.Conn == conn` и бездействует, если уже не «наш» сокет.
- **Сессия игрока**: на `create_room`/`join_room` сервер возвращает `token` (2×`randID`). Клиент хранит `{code, token, name}` в `localStorage` под ключом `spyfall_session_v1` и на загрузке страницы / на `ws.onclose` шлёт `reconnect`. Сервер ищет `Player` по паре `Token + Name` в нужной `Room`. Если найден и ещё в grace period — подменяется `Conn`, шлётся `reconnected` с полным снапшотом (`state`, `role`, `location`, `alive`, `spy_count`, `accuse`, `game_over` если `over`). Если нет — `error`, клиент чистит `localStorage`.

### Протокол сообщений

Все сообщения это JSON-конверты `{type, payload}` (см. `Msg` / `enc`). Список ниже — это полный контракт между сервером и `static/index.html`, и добавление нового взаимодействия означает правки с обеих сторон.

- **Клиент → сервер**: `create_room`, `join_room`, `reconnect`, `start_game`, `chat`, `accuse`, `accuse_vote`, `spy_guess`, `turn_confirm` (`turn_id`), `round_vote` (`vote_id`, `target_id`; пустой ID — пропуск).
- **Сервер → клиент**: `error`, `room_joined`, `reconnected`, `player_list`, `game_started`, `chat_msg`, `accuse_started`, `accuse_result`, `spy_guess_result`, `game_over`, `round_state`, `round_vote_result`.

`game_started` — единственное сообщение, у которого payload отличается по получателям: шпионам уходит `location: null` и `role: "spy"`, всем остальным настоящая локация и `role: "civilian"`. Остальные серверные сообщения всем идентичны. После каждой смерти (`accuse_result.target_died = true` или неудачный `spy_guess`) сервер дополнительно рассылает `player_list` — клиент держит `alive`-флаги в сторе и использует как источник истины.

### Круги вопросов

- `Room.Turn` хранит пару игроков и подтверждения; очередь состоит из живых игроков в порядке входа. После двух подтверждений отвечавший становится спрашивающим. Последний спрашивает первого.
- После круга `RoundVote` переводит комнату в `voting`. Все живые выбирают подозреваемого; строгое большинство от всех живых игроков устраняет цель. Таймер — 30 секунд, отсутствие голоса означает пропуск.
- `turn_id` и `vote_id` защищают новые вопросы/голосования от запоздалых сообщений. Клиент игнорирует старые `round_state.revision`.
- `reconnected.round_state` восстанавливает очередь и отметки голосования без раскрытия выбранных подозреваемых. Временный обрыв не сбрасывает подтверждения. `syncTurn` обновляет пару после смерти/удаления игрока.

### Правила игры, зашитые в сервер

- `SpyCount` выбирается при создании комнаты (1–`maxSpies` = 3) и фиксируется до конца раунда.
- `start_game` требует `len(Players) >= SpyCount + 2` (минимум 2 мирных) и запускается только хостом.
- Таймера нет. Игра длится до победы одной из сторон.
- У каждого игрока есть флаг `Alive`. Мёртвые не голосуют, не обвиняют, не могут быть целью обвинения, шпион-мертвец не может угадывать. Чат мёртвым не режется.
- Голосование: большинство «виновен» убивает цель (`Alive = false`), игра **не** заканчивается автоматически — продолжается, пока либо не убиты все шпионы (`all_spies_caught` → побеждают мирные), либо не убиты все мирные (`all_civilians_dead` → побеждают шпионы). Если большинства нет, ничего не происходит.
- Угадывание шпионом: правильно → `spy_guessed`, шпионы побеждают (весь раунд). Неправильно → только этот шпион умирает, игра продолжается.
- `game_over.spies` — массив `{id, name}` всех игроков, бывших шпионами (и живых, и мёртвых). `winner` — `"spies"` или `"civilians"`.
- Локации лежат в захардкоженном списке `allLocations` (25 штук, на русском). Если меняешь его, меняется и то, что клиент показывает в модальном окне мест для шпиона (приходит в `game_started.locations`).
